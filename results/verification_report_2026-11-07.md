# 検証結果レポート

Qwen-AgentWorld-35B-A3B（GGUF）を Apple M3 Pro 上の llama.cpp で動かし、領域、長い状態追跡、紛らわしいシェル操作、量子化を調べた。実施日は 2026-11-07 である。数値は各シナリオ 1 回の実行結果であり、シナリオ中のコマンドはこの Mac では実行していない。出力はすべてモデルの予測である。

## 1. 環境

| 項目 | 値 |
|---|---|
| ホスト | MacBook Pro、Apple M3 Pro（CPU 12 コア、GPU 18 コア）、物理メモリ 36.00 GiB |
| 推論 | llama.cpp `llama-server` build `b8680-15f786e65`。`127.0.0.1:8080`、`-ngl 99 -c 32768 -fa on --jinja --reasoning-format deepseek` |
| モデル | `unsloth/Qwen-AgentWorld-35B-A3B-GGUF`。サーバーが返す総パラメータ数は 34,660,610,688 |
| 採点 | `scenarios/catalog.py` の文字列オラクル。温度 0.6、`top_p` 0.95、`top_k` 20、`seed` 1 |
| 主系列の量子化 | `UD-Q4_K_M`、20.61 GiB |

活性化パラメータ数は今回計測していない。プロジェクトの README は 3B と記載している。

Web、Android、OS は AgentWorldBench と同じく、毎ターンこちらが書いた画面を `Current State` として渡した。測っているのは、その画面に対する 1 手の予測である。Terminal、MCP、Search、SWE は、画面を書き戻さず、過去の予測だけを履歴に残した。

MCP は `/notes/a.txt` の作成、`/notes/c.txt` への移動、移動元の不在、移動先の内容 `alpha-stone`、一覧の `b.txt` と `c.txt` まで一致した。SWE は `swe-token-9` の作成と実行のあと、編集後の再実行が `swe-token-3` になり、削除後の Read は不在になった。OS は A1 を `42` から `100` に更新したあとも B1 の `7` が残った。

自動採点で落ちた 3 件の中身は次のとおりである。

- Web のターン 1 は、空の Name 欄に値 `Kepler` が入った。URL は `http://lab.example/` のままであった。表記がベンチで見る `: Kepler` ではなく `[value="Kepler"]` であったため、文字列一致が落ちた。同じシナリオのターン 4 は `: Galileo` であり、表記はターン間で揺れた。
- Android の上限 8192 では、保存済みノートを開き直すターンが `finish_reason=length` となり、観測が空であった。上限 16384 では完了トークン 12,184、思考 37,547 文字で終わり、編集欄は `text="Kepler note"` であった。状態の誤りではなく、思考がトークン上限を使い切った。
- Search のターン 8 は、抽出本文に `299,792,458` と見出し `Speed of light` があった。落ちた条件は、検索結果タイトル `Speed of light - Wikipedia` の接尾辞が本文に無いことである。記憶の 6 ターンは、`halley` の追加、`neowise` への更新、削除後の `Key not found` まで一致した。

## 3. 33 ターンのターミナル

`long_terminal` は 32/33、壁時間 1,449 秒、完了トークン 40,357、プロンプトトークン 3,153 から 5,989 である。文脈長 32,768 には収まった。

追跡した内容は、`TOKEN_ALPHA` から `TOKEN_ETA` までの作成、改名、追記、兄弟ファイルの削除、上書き、`find`、`rm -r`、最後の `pwd` である。ターン 33 の `pwd` は `/app/lab` であり、`src/a_renamed.txt` には `TOKEN_ALPHA` と `TOKEN_EPSILON` が残っていた。この 33 ターンの中で、ファイルの中身と位置の追跡は崩れていない。

自動採点の不合格はターン 15 だけである。出力は次であり、作業ディレクトリの移動自体は正しい。

```
root@demo:/app/lab/data# cd /app/lab
root@demo:/app/lab#
```

不合格理由は、コマンドエコー行に残る移動前プロンプト `root@demo:/app/lab/data#` を「残ってはいけない」としたオラクルである。ターン 16 以降のプロンプトは `root@demo:/app/lab#` であった。

## 4. 紛らわしいシェル操作

`tricky_terminal` は 24/24、壁時間 1,232 秒、完了トークン 34,144、プロンプトトークン 3,148 から 5,276 である。次の結果は Linux の bash と一致した。

- `mv` による改名のあと、旧名は無く、新名に内容が残る。
- 存在しないディレクトリへの `mv` は失敗し、元のファイルは残る。
- 既存ファイルへの `mv` は移動元の内容で上書きする。
- `echo "$FOO"` は展開され、`echo '$FOO'` は `$FOO` のままである。
- `export FOO=apple` のあと、`FOO=banana echo "$FOO"` は `apple` を出す。前置代入は同じ単純コマンドの `$FOO` 展開に効かず、次のコマンドにも残らない。
- `echo "x${FOO}y"` は `xappley`、`tr a-z A-Z` は `APPLE` である。
- 存在しないファイルを `wc -l` にパイプすると、`No such file or directory` と `0` の両方が出る。
- `(cd sub && pwd) && pwd` は `/app/box/sub` と `/app/box` をこの順で出す。

## 5. 量子化

比較に使ったのは 10 ターンの `quant_probe`（バイト数 12、`mv`、単引用符、前置代入）である。温度と `seed` は主系列と同じである。チェックリストの IQ4_XS、Q5、Q8 は、配布ファイル名では `UD-IQ4_XS`、`UD-Q5_K_M`、`Q8_0` である。既定の `UD-Q4_K_M` も同じプローブにかけた。

| 量子化 | ファイル | サイズ | 正答 | 生成速度 | 1 ターンの壁時間 | 実施時刻 |
|---|---|---|---|---|---|---|
| IQ4_XS | `UD-IQ4_XS` | 16.56 GiB | 10/10 | 30.0 tok/s | 40.8 秒 | 22:18:19–22:25:07 |
| Q4_K_M | `UD-Q4_K_M` | 20.61 GiB | 10/10 | 26.7 tok/s | 44.2 秒 | 22:10:43–22:18:05 |
| Q5 | `UD-Q5_K_M` | 24.64 GiB | 10/10 | 26.4 tok/s | 47.1 秒 | 22:25:35–22:33:26 |
| Q8 | `Q8_0` | 34.37 GiB | 未実行 | — | — | — |

この 10 ターンでは正答に差はなかった。生成速度は IQ4_XS が最も速く、Q5 は Q4_K_M とほぼ同じであった。Q4_K_M の 1 ターン目だけ 10.1 tok/s であった。直前まで二つの GGUF をダウンロードしており、2 ターン目以降は 28.3 tok/s である。IQ4_XS と Q5 の 1 ターン目を除いた速度は、それぞれ 30.5 tok/s と 26.7 tok/s である。

`Q8_0` は Content-Length が 34.37 GiB であり、物理メモリ 36.00 GiB の 80% を超える。`scripts/compare_quants.py` はこの条件でロードしない。ファイルは取得していない。`UD-Q8_K_XL` は 35.58 GiB であり、同じ理由で対象にしていない。

六領域と 33 ターンは `UD-Q4_K_M` だけである。量子化による精度差は、この 10 ターンの外では測っていない。

## 6. 所見

状態の追跡は、今回のターミナル課題では 33 ターンと、`mv`、パイプ、引用符、前置代入、サブシェルを含めて維持された。MCP と SWE でも、作成した値は後続の Read と実行に残った。

壁時間の大部分は思考トークンである。観測そのものは短い。Android の開き直しは思考 37,547 文字を要し、上限 8192 では観測が空になる。UI シナリオの `max_tokens` は 16384 を下回らない。

自動採点の不合格 4 件のうち、モデルの出力を読んで状態の誤りと残るのは Web の値表記だけである。Android はトークン上限、Search はタイトル接尾辞、長いターミナルのターン 15 はコマンドエコーを禁止したオラクルである。

量子化を上げても、このプローブの正答は変わらなかった。同じ正答なら、このマシンでは IQ4_XS が速く、ファイルも小さい。Q8 は 36 GiB のメモリには載せない。

## 7. この結果が覆わないこと

- 各数値は `seed` 1 の 1 回である。分散は測っていない。
- 採点は論文の 5 次元 judge ではない。期待する部分文字列と正規表現である。
- Web、Android、OS は、モデルが自分の前画面を記憶できるかは測っていない。毎ターン、正解の画面を渡している。
- 長いシナリオと六領域は `UD-Q4_K_M` だけである。
- `Q8_0` の精度と速度は未計測である。
